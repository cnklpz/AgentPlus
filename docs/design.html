AgentPlus

一个地方管理 Claude Code、Codex、Gemini CLI、OpenCode 等编码 Agent 的服务商和模型。一键切换，改动先预览、可回滚；顺带把 Codex Fast、当前服务商这类"看不见的状态"显示出来。

首批 Agent
Claude Code · Codex CLI
后续 Agent
Gemini CLI · OpenCode · Qwen Code
形态
桌面 GUI + 托盘 + CLI
平台
Windows · macOS · Linux · WSL

01背景与目标

各家编码 Agent 都能换服务商、换模型，但每家的配置文件、字段名、协议都不一样。

现在的麻烦

  • JSON、TOML、环境变量三套写法，字段名各不相同，换一次中转要改好几个文件。
  • 手改容易改坏：TOML 注释被覆盖，PowerShell 写出带 BOM 的文件导致解析失败。
  • /model 选择器只列官方模型，自己服务商的模型选不到。
  • 状态看不见：Codex 默认是否开了 Fast、Claude Code 这会儿走的是哪个服务商。
  • 本机、WSL、服务器各一份配置，互相不同步。

AgentPlus 要做到

  • 服务商和模型只录一次，按 Profile 一键应用到多个 Agent。
  • 只改需要改的字段，其余内容（注释、顺序、换行风格）原样保留。
  • 每次写入前给出 diff，写入后自动备份，随时回滚。
  • 自定义模型列表能进入各 Agent 的模型选择流程。
  • 桌面、命令行、WSL、多台设备用同一套配置。

不做（首版）

  • 不做 Agent 本身，不包装、不替换 CLI。
  • 不做 API 中转或计费平台。
  • 不把密钥托管到任何云端。

和现有工具的区别

开源的 cc-switch 已经做了 Claude Code / Codex 的服务商切换。AgentPlus 的差异在：更多 Agent 统一抽象、模型目录与选择器注入、状态可视化（Fast / 状态栏）、CLI + WSL + 多设备同步。

03核心概念

四个概念覆盖全部场景。关键设计：一个服务商可以有多个协议端点，适配器自己挑能用的那个。

概念是什么例子
Provider 服务商一个账号 + 若干协议端点 + 一把密钥官方 Anthropic、官方 OpenAI、某中转站（同时有 Anthropic 和 Responses 端点）
Model 模型挂在服务商下，带显示名、上下文长度、能力标签claude-sonnet-5，标签"编码 / 长上下文"
Profile 方案一组"Agent → 服务商 + 模型 + 选项"的绑定"日常"：Claude 走中转 A，Codex 走官方并开 Fast
Adapter 适配器把绑定翻译成某个 Agent 的具体配置改动Codex 适配器把绑定写成 config.toml 的几行

适配器接口

"计算改动"和"写入"分开，这样 GUI 能先展示 diff，CLI 能支持 --dry-run。

crates/core/src/adapter.rs
pub trait AgentAdapter {
    fn id(&self) -> AgentId;
    fn detect(&self, host: &Host) -> Option<Installation>;        // 安装路径、版本、所在主机（本机 / WSL）
    fn read(&self, inst: &Installation) -> Result<AgentState>;     // 当前服务商、模型、Fast 等
    fn plan(&self, inst: &Installation, b: &Binding) -> Result<Patch>; // 只计算，不落盘
    fn apply(&self, patch: Patch) -> Result<Receipt>;              // 备份 + 原子写 + 回读校验
    fn capabilities(&self) -> Caps;                                  // 支持的协议、是否有 Fast、状态栏等
}

05功能设计

五块：切换、模型列表、Codex Fast、状态栏、小工具。

5.1 一键切换 Profile

两种应用方式，用户按场景选：

写入模式（默认）

把配置写进各 Agent 的配置文件，之后直接运行 claude / codex 就生效。适合"这段时间都用这个"。写完提示哪些正在运行的 Agent 需要重启。

启动器模式

ap run codex -p fast-relay 只给这一个进程注入环境变量和 -c 覆盖参数，不改任何文件。适合两个终端同时用不同服务商。

5.2 自定义模型列表

模型目录有三个来源：手动添加、从服务商的 /v1/models 拉取、内置常用预设。目录支持改显示名、排序、隐藏、打标签（快 / 便宜 / 长上下文）。难点在于怎么让它出现在各 Agent 里：

Agent注入方式限制
Claude Code 把 Opus / Sonnet / Haiku 三个槽位映射到 ANTHROPIC_DEFAULT_*_MODEL，在 /model 里选别名即落到自定义模型；需要整份列表时写 availableModels。额外单个模型可用 ANTHROPIC_CUSTOM_MODEL_OPTION 待验证。 availableModels 是替换而非追加，写之前要把用户想保留的官方模型一并列进去。
Codex CLI 每个模型生成一个 [profiles.<名字>]，codex -p <名字> 切换；AgentPlus 的托盘和 ap 提供快速选择。 Codex 的 /model 选择器目前不显示自定义服务商的模型（openai/codex#22160）。
OpenCode 直接写 provider.<id>.models。 原生支持，无额外限制。

5.3 Codex Fast 显示与开关

Fast 用更高的额度消耗换更快的响应。AgentPlus 负责三件事：读出默认状态、一键开关、让 Codex 自己的状态栏也显示出来。

~/.codex/config.toml — AgentPlus 只改这几处
service_tier = "fast"          # 默认开启 Fast

[features]
fast_mode = true

[tui]
# 在用户已有条目后追加 "fast-mode"，不打乱原有顺序
status_line = ["model-with-reasoning", "context-remaining", "git-branch", "fast-mode"]
  • 界面徽标：侧栏 Codex 条目旁显示 FAST，悬停说明"默认开启，来自 config.toml"。
  • 开关前检查：当前服务商不是 OpenAI 官方时置灰——第三方端点可能拒绝 service_tier，写进去反而报错。
  • 成本提示：开启时提示额度消耗高于 Standard，具体倍率链接到 OpenAI 的 Speed 说明页。

会话里用 /fast 临时切换是运行时状态，不写盘，AgentPlus 看不到。所以界面上统一写"默认值"，实时状态交给 Codex 状态栏里的 fast-mode 项显示。

5.4 状态栏注入

  • Claude Code：设置 statusLine 为 ap statusline claude，输出"服务商 · 模型 · 延迟"，一眼看出当前走哪条线路。
  • Codex：状态栏只支持内置项，不能跑自定义命令（openai/codex#20244 仍在讨论）。AgentPlus 提供勾选列表，编辑 [tui].status_line。

06多端方案

"多端"分四层：多个桌面系统、无界面环境、Windows 里的 WSL、多台设备之间。

端做法交付物
桌面Tauri 2 一套代码打三个平台Windows MSI / NSIS，macOS dmg（Universal），Linux AppImage / deb
命令行同一个核心库编译出 ap，用于 SSH 服务器、容器、CI单文件二进制，cargo install / npm 包装 / 各平台包管理器
WSLWindows 端枚举 WSL 发行版，把每个发行版当作独立"主机"，通过 \\wsl.localhost\<发行版>\home\<用户> 读写；也可在 WSL 里直接用 Linux 版 ap桌面端"主机"切换器
多设备同步服务商、模型目录、Profile 加密后同步到 WebDAV、私有 Git 仓库或网盘文件夹；密钥默认不同步，可选用口令端到端加密后同步设置页"同步"
手机（后期）不在手机上跑 Agent，只做遥控器：看各设备当前配置、通过同步通道下发 Profile 切换。Tauri 2 支持 iOS / Android，复用前端M4 评估
CLI 用法草案
ap ls                               # 列出检测到的 Agent 及当前服务商 / 模型 / Fast
ap use daily                        # 应用 Profile 到所有已绑定的 Agent
ap use daily --agent codex --dry-run  # 只看 diff
ap model codex gpt-5-codex --effort high
ap fast codex on                    # 写 service_tier + features + status_line
ap run claude -p relay-b            # 启动器模式，不改文件
ap rollback                         # 回到上一次应用前
ap --host wsl:Ubuntu ls             # 操作 WSL 里的配置

08可靠性与密钥

配置工具最怕的是把用户能用的环境改坏。每次写入都走同一条管线。

写入管线

  1. 读取并解析：保留格式地解析（TOML 用 toml_edit，JSON 保持键顺序），记下原编码、BOM、换行风格。
  2. 计算改动：适配器只生成需要变化的字段，得到 Patch。
  3. 展示 diff：GUI 右栏 / CLI --dry-run；检测到外部改动（文件监听）时重新计算。
  4. 备份：原文件复制到 ~/.agentplus/backups/<时间>/，保留最近 50 份。
  5. 原子写入：先写同目录临时文件，再重命名替换，避免写到一半断电留下半个文件。
  6. 回读校验：重新解析写好的文件，失败则自动从备份恢复并报告原因。
  7. 提示重启：列出正在运行、需要重启才能生效的 Agent 进程。

密钥

  • 存放在系统钥匙串：Windows 凭据管理器、macOS Keychain、Linux Secret Service。AgentPlus 自己的文件里只有引用。
  • Claude Code：写 apiKeyHelper 指向 ap key get relay-a，由 Claude Code 运行时取密钥，settings.json 里不出现明文。
  • Codex：服务商配置用 env_key 引用环境变量，由启动器模式注入；如果用户坚持写入 auth.json，界面明确提示这是明文。
  • 日志、导出、同步内容一律脱敏，只显示密钥末 4 位。

12风险与待定

风险应对
Agent 配置格式变化快适配器声明支持的版本范围；fixture 快照测试；不认识的字段原样保留；检测到未知版本时降级为只读并提示
Codex 选择器不显示自定义模型用 [profiles.*] + 托盘 / CLI 绕开；跟进 openai/codex#22160，官方支持后切换
Fast 的会话态不可见界面只称"默认值"，实时状态交给 Codex 状态栏
第三方端点不认 service_tier非官方服务商时禁用 Fast 开关，并说明原因
Agent 运行中改配置检测进程，写后提示重启；启动器模式不受影响

需要你拍板

首批只做 Claude Code + Codex，还是一开始就带上 OpenCode？OpenCode 自带多服务商，适配成本低，但用户群和前两者重叠较少。
"多端"的重点是哪一层？本方案按"三大桌面系统 + CLI + WSL + 多设备同步"设计，手机放在 M4。如果你更想要手机端或网页端，路线图要调整。
要不要做协议转换代理？做了之后任何服务商都能给任何 Agent 用，但工具就从"配置管理"变成"网络服务"，复杂度和维护成本明显上升。
是否需要团队共享？比如团队统一下发服务商和模型目录。需要的话同步层要从"个人加密"改成"带权限的共享"。
