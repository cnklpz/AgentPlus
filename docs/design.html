AgentPlus

One place to manage the providers and models of coding agents such as Claude Code, Codex, Gemini CLI and OpenCode. Switch in one click, preview every change and roll it back; along the way, surface "invisible state" such as Codex Fast and the current provider.

First agents

Later agents
Gemini CLI · OpenCode · Qwen Code
Form

01Background and goals

Every coding agent lets you change the provider and model, but each one uses different config files, field names and protocols.

What hurts today

  • Three styles (JSON, TOML, environment variables), each with its own field names; switching relays means editing several files.
  • Hand edits break things easily: TOML comments get overwritten, and PowerShell writes files with a BOM that then fail to parse.
  • The /model picker lists only official models, so models from your own provider can't be selected.
  • State is invisible: whether Codex has Fast on by default, which provider Claude Code is using right now.
  • The local machine, WSL and servers each have their own config, and none of them stay in sync.

What AgentPlus should do

  • Enter providers and models once, and apply them to several agents in one click through a Profile.
  • Change only the fields that need changing, and keep everything else (comments, order, line endings) as it was.
  • Show a diff before every write, back up automatically after writing, and allow rollback at any time.
  • Get custom model lists into each agent's model selection flow.
  • Use one set of configs across desktop, command line, WSL and multiple devices.

Out of scope (first release)

  • Not an agent itself; it doesn't wrap or replace any CLI.
  • Not an API relay or billing platform.
  • Keys are never hosted in any cloud.

How it differs from existing tools

The open-source cc-switch already switches providers for Claude Code / Codex. AgentPlus differs in: a unified abstraction over more agents, a model catalog with picker injection, state visibility (Fast / status line), and CLI + WSL + multi-device sync.

Adapter interface

"Compute the change" and "write it" are separate steps, so the GUI can show a diff first and the CLI can support --dry-run.

crates/core/src/adapter.rs
pub trait AgentAdapter {
    fn id(&self) -> AgentId;
    fn detect(&self, host: &Host) -> Option<Installation>;        // install path, version, host (local / WSL)
    fn read(&self, inst: &Installation) -> Result<AgentState>;     // current provider, model, Fast, etc.
    fn plan(&self, inst: &Installation, b: &Binding) -> Result<Patch>; // compute only, nothing written
    fn apply(&self, patch: Patch) -> Result<Receipt>;              // backup + atomic write + read-back check
    fn capabilities(&self) -> Caps;                                  // supported protocols, Fast, status line, etc.
}

05Features

Five parts: switching, model lists, Codex Fast, status lines, and small tools.

5.1 One-click Profile switching

Two ways to apply, depending on the situation:

Write mode (default)

Writes the config into each agent's config files, so running claude / codex afterwards just works. Suits "I'll use this for a while". After writing, it lists which running agents need a restart.

Launcher mode

ap run codex -p fast-relay injects environment variables and -c overrides into that one process only, without touching any file. Suits two terminals using different providers at the same time.

5.2 Custom model lists

The model catalog has three sources: added by hand, fetched from the provider's /v1/models, and built-in common presets. Entries can be renamed, reordered, hidden and tagged (fast / cheap / long context). The hard part is getting them to show up in each agent:

AgentHow to injectLimits
Claude Code Map the Opus / Sonnet / Haiku slots to ANTHROPIC_DEFAULT_*_MODEL, so picking an alias in /model lands on the custom model; write availableModels when a whole list is needed. A single extra model may use ANTHROPIC_CUSTOM_MODEL_OPTION to verify. availableModels replaces the list rather than appending to it, so the official models the user wants to keep must be listed too.
Codex CLI Generate one [profiles.<name>] per model and switch with codex -p <name>; the AgentPlus tray and ap offer a quick picker. Codex's /model picker currently doesn't show models from custom providers (openai/codex#22160).
OpenCode Write provider.<id>.models directly. Supported natively, no extra limits.

5.3 Showing and toggling Codex Fast

Fast trades higher usage for faster responses. AgentPlus does three things: read the default, toggle it in one click, and make Codex's own status line show it too.

~/.codex/config.toml — AgentPlus changes only these lines
service_tier = "fast"          # Fast on by default

[features]
fast_mode = true

[tui]
# Append "fast-mode" after the user's existing items, keeping their order
status_line = ["model-with-reasoning", "context-remaining", "git-branch", "fast-mode"]
  • UI badge: a FAST badge next to Codex in the sidebar; hovering explains "On by default, from config.toml".
  • Check before toggling: greyed out when the current provider isn't official OpenAI — third-party endpoints may reject service_tier, and writing it would only cause errors.
  • Cost note: when turning it on, warn that usage is higher than Standard, linking to OpenAI's Speed page for the exact multiplier.

Switching with /fast inside a session is runtime state that isn't written to disk, so AgentPlus can't see it. The UI therefore always says "default", and leaves the live state to the fast-mode item in Codex's status line.

5.4 Status line injection

  • Claude Code: set statusLine to ap statusline claude, which prints "provider · model · latency", so you can see at a glance which route is in use.
  • Codex: the status line only supports built-in items and can't run custom commands (openai/codex#20244 is still under discussion). AgentPlus offers a checklist that edits [tui].status_line.

08Reliability and keys

The worst thing a config tool can do is break a working setup. Every write goes through the same pipeline.

Write pipeline

  1. Read and parse: parse while preserving formatting (toml_edit for TOML, key order kept for JSON), and record the original encoding, BOM and line endings.
  2. Compute the change: the adapter generates only the fields that need to change, producing a Patch.
  3. Show the diff: in the GUI's right column / CLI --dry-run; recompute when an external change is detected (file watching).
  4. Back up: copy the original file to ~/.agentplus/backups/<time>/, keeping the latest 50.
  5. Atomic write: write a temp file in the same folder first, then rename it over the original, so a power cut mid-write never leaves half a file.
  6. Read-back check: re-parse the written file; on failure, restore from the backup automatically and report why.
  7. Restart prompt: list running agent processes that need a restart for the change to take effect.

Keys

  • Stored in the system keychain: Windows Credential Manager, macOS Keychain, Linux Secret Service. AgentPlus's own files contain only references.
  • Claude Code: write apiKeyHelper pointing to ap key get relay-a, so Claude Code fetches the key at runtime and no plaintext appears in settings.json.
  • Codex: provider config references an environment variable through env_key, injected by launcher mode; if the user insists on writing auth.json, the UI states clearly that it's plaintext.
  • Logs, exports and synced content are always redacted, showing only the last 4 characters of a key.

12Risks and open questions

RiskMitigation
Agent config formats change quicklyAdapters declare the version range they support; fixture snapshot tests; unknown fields kept as they are; fall back to read-only with a notice when an unknown version is detected
Codex picker doesn't show custom modelsWork around it with [profiles.*] + tray / CLI; follow openai/codex#22160 and switch once it's officially supported
Fast's in-session state is invisibleThe UI only says "default"; live state is left to Codex's status line
Third-party endpoints reject service_tierDisable the Fast toggle for unofficial providers and explain why
Config changed while an agent is runningDetect processes and prompt for a restart after writing; launcher mode is unaffected

Decisions needed from you

Start with only Claude Code + Codex, or include OpenCode from the beginning?OpenCode has built-in multi-provider support, so adapting it is cheap, but its users overlap less with the other two.
Which layer of "multi-platform" matters most?This design assumes "three desktop OSes + CLI + WSL + multi-device sync", with the phone in M4. If you'd rather have a mobile or web client, the roadmap needs to change.
Build a protocol-translation proxy?With it, any provider could serve any agent, but the tool would turn from "config management" into "a network service", with clearly higher complexity and maintenance cost.
Is team sharing needed?For example, a team pushing out a shared provider list and model catalog. If so, the sync layer has to change from "personal encryption" to "sharing with permissions".
